Branch #10 리소스 로드 시스템 어드레서블 개편

Commit [Refactor] ResourceManager 1차 리팩토링 종료

변경 요약

ResourceManager의 책임을 “콘텐츠 동기화 오케스트레이션”에서 분리하고,
Addressables 기반 로드/언로드 실행자 + 공용 IO(파일/네트워크) + 런타임 저장소로 재정의했습니다.

staticKey 단위 동시성 규약(Task tailing)을 도입하여
같은 키 충돌만 직렬화하고, 다른 키는 병렬성을 유지하도록 구조를 고정했습니다.


상세 변경 내용
1. RM 책임 재정의 및 역할 분리
    RM은 실행자/저장소 역할로 고정
    - Addressables Load/Unload 수행
    - 로드된 리소스 Get 제공
    - 파일/네트워크 IO 유틸 제공
    콘텐츠 동기화(Manifest→Catalog→Bundle) 오케스트레이션은 CMS로 분리

2. TypeMapContainer + AccessMode 기반 저장소 통합
    리소스 캐시를 타입/키 기반 저장소로 통일
        - TypeMapContainer[] assetContainers 도입
        - AccessMode.Public : 외부 조회용 리소스
        - AccessMode.Internal : 운영 상태(Task tail, AsyncOperationHandle 등)
    AllocateTypeMap/Register/UnRegister/TryGetAsset_Internal 규약 확정

3. staticKey 단위 동시성 제어(Task tailing) 확정
    동일 staticKey 요청은 Internal에 Task<IOResult> tail로 직렬화
        - 선행 작업(previousTask) await 후 실행
        - finally에서 “내가 등록한 tail만” 제거하여 정합성 유지
    결과
        - 같은 키 중복 작업/경합 방지
        - 다른 키는 동시 로드/언로드 허용

4. Addressables 핸들 수명 관리 규약 고정
    Internal에 AsyncOperationHandle을 보관하고 Public 등록 성공을 기준으로 상태 확정
    실패/중단 시 Release 누수 방지
        - 로드 실패 / 공개 등록 실패 시 핸들 정리 후 Release
        - 언로드는 “있으면 제거하고 있으면 Release” 멱등 동작으로 단순화
    “공개 리소스 없음 + 내부 핸들만 존재” 케이스도 정리 루트에 포함

5. StreamContainer 기반 경로 Lease 모델 도입
    외부가 파일을 직접 열지 않고 RM이 소유권을 유지한 채 사용권만 제공
        - 중복 lease 차단 옵션(denyDuplicatePathLease)
        - Task 완료 시 자동 Dispose 바인딩
        - Release를 통한 조기 반납 지원
    파일 접근 경합/누수 방지 기반 마련

6. 공용 IO 유틸 통합 및 원자적 파일 작업 강화
    파일/네트워크 IO를 RM 공용 함수로 수렴
        - ReadAllBytesAsync / DownloadBufferAsync / DownloadFileAsync / SaveAsync / Delete
    .tmp → atomic move(+ .bak 롤백) 패턴을 공통 규약으로 통일
        - 저장/다운로드 중단 시 부분 파일 제거
        - 커밋 실패 시 백업 복구로 로컬 일관성 보장

7. 로깅/실패 코드 경로 정리
    IOResult/IOFailReason 기반으로 실패 사유를 구조화
    예외 루트에서 자원 정리(Release/Dispose/임시파일 삭제)를 우선 보장하도록 정리
