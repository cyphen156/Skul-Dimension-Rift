    [Feat] 도메인 오브젝트 체계 확정

변경 요약
    DomainKey(32bit) 기반의 도메인 식별 규약을 최종 확정하였습니다.
    DomainObject / DomainIdentity 중심의 풀 계약 구조를 정리하고 고정했습니다
    인스턴스 수명(instanceId, scopeId)과 정적 식별(staticKey)을 명확히 분리했습니다
    도메인 오브젝트는 풀을 통해서만 생성/회수되도록 계약 강제합니다.

상세 변경 내용
    1. DomainKey / DomainIdentity 체계 확정
        DomainKey를 중심으로 한 도메인 식별 규약을 최종 확정
        DomainIdentity는 런타임 인스턴스 수명 관리 전용 구조로 한정

    2. DomainKey 비트 레이아웃 고정
        Domain / Grade / Role / Class / Instance 비트 구성 확정
        레이아웃 변경 가능성 제거

    3. StaticKey 기준 풀 운용
        Instance가 제거된 StaticKey를 모든 풀의 기준 키로 사용
        인스턴스 ID는 런타임 수명 관리 용도로만 사용
 
    4. Class 필드 역할 정리
        Class 필드는 논리 단위(main/sub) 인덱싱만 허용
        실제 프리팹 매핑은 런타임 데이터에 위임
        도메인 체계의 과도한 확장을 방지
    
    5. DomainObject 계약 정리
        모든 풀 대상 오브젝트는 DomainObject 필수 보유
        GetIdentity() 제거
        GetIdentityRef()만 허용하여 식별자 구조체의 무분별한 값 복사 차단
        외부 접근은 파생 값(staticKey, objectKey, domain)만 허용
        acquired / releasing 플래그를 통한 풀 계약 상태 관리 확정

    6. 풀 계약 위반 감지 로직 확정
        OnDisable / OnDestroy에서 풀 계약 위반 감지
        에디터 강제 종료/리로드 상황을 고려하여
        Application.isPlaying 가드로 런타임 계약 범위 명확화
        Despawn 경로를 거치지 않은 Disable / Destroy는 즉시 에러 처리

    7. Pool / PoolManager 구조 확정
        풀은 StaticKey 단위로만 관리 (서브풀 개념 제거)
        scopeId는 서브스테이지 / 논리 그룹 식별 용도로만 사용
        서브스테이지 전환 시:
            오브젝트 Despawn
            풀은 유지

        씬 전환 시:
            풀 전체 Dispose

    8. ObjectSpawner 클래스 역할 변경
        기존 싱글턴 매니저 구조 제거
        풀 접근 진입점 역할만 담당하도록 Static Utility 클래스로 변경
        PoolManager에 대한 직접 의존을 차단하고,
        Spawn / Despawn 호출의 단일 진입점으로 역할 고정

    참고 사항
        본 커밋은 StageManager 실제 구현 이전 단계
        스테이지 데이터 로드, 프리팹 매핑, 전환 흐름은
            이후 풀 실동 테스트 완료 후 단계적으로 연결 예정
        도메인/아이덴티티/풀 계층은 본 커밋을 기준으로 동결
